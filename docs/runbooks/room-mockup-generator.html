Room Mockup Generator

Turn one poster file into a wall of candidate room shots. You supply blank-wall room photographs and a rectangle; the tool frames the artwork, drops two shadows under it, and hands you a contact sheet to pick from.

Superseded, 2026-09-03. The straight-on placement rectangle and room-templates.json this runbook describes are gone. Rooms are now measured as a wall plane in room-<id>.json and one bare-wall room serves every poster shape. Read docs/ROOM-MOCKUP-PIPELINE.md and packages/api/src/database/room-templates/README.md instead; measure with packages/api/tools/room-measure.html. The command names below are still right.

What it does

Every product's gallery is one main image plus a few room mockups — the artwork hanging on a wall in a furnished room. Producing those by hand meant photographing each framed piece, or compositing in an image editor and uploading one file at a time. This tool does it from a single artwork file.

Pipeline
poster artwork ──┐
                 ├─▶ mockups:rooms ──▶ out/<poster-name>/
room templates ──┘                      ├── room-<template-id>.jpg   × N
  .cache/room-templates/*.jpg           ├── framed-main.jpg
  + room-templates.json                 └── contact-sheet.jpg
                                                 │
                                    you delete the ones you don't like
                                                 │
                              admin upload   or   bulk import manifest

It runs entirely offline. It reads local files, writes local files, and exits — no database, no cloud storage, no network. Roughly 1.2 seconds per image.

What lands in the output folder

  • room-<template-id>.jpg One per room template. These become the product's room mockups.
  • framed-main.jpg The artwork framed on a plain mat ground. Upload this as the product's main image. Uses the first selected template's moulding, so it shifts if you reorder templates in room-templates.json or change which ones --only selects.
  • contact-sheet.jpg Every candidate in one numbered grid. This is the only file you need to open to choose.
Filenames are a contract

Those names are what the bulk catalogue import expects in its mainImage and roomImages columns. Renaming them breaks the handoff.

How the shadow works

Worth understanding before you tune anything, because it is the whole reason the output looks like a photograph rather than a sticker.

A single drop shadow always reads as a sticker pasted onto a photo. Two shadows read as an object with thickness: the contact shadow is the edge meeting the wall, and the ambient shadow is the body of the piece standing off it.

Both are scaled from one number per frame, depthRatio. Their direction comes from the template's light field, which must match the way the room photograph is actually lit — get that backwards and the composite reads as fake immediately.

Depth changes size, not darkness

A thicker frame casts a larger shadow, not a darker one. Blur and offset scale with depthRatio; opacity is fixed. Darkening with depth would read as the room's lighting changing rather than the object changing.

This is also why frameless stretched canvas gets the largest depthRatio of any frame: with no moulding face, the shadow is the only depth cue it has.

Before you start

The tool ships unable to run

room-templates.json is an empty array until blank-wall room photographs exist. Until you add some, every run stops with No room templates defined — nothing to render. That is intended, not a bug: it refuses loudly rather than producing nothing quietly.

What makes a usable room photograph

Templates are the real cost of this feature. The code cannot rescue a bad one.

RequirementWhy
Straight-on wall An angled wall needs a four-point perspective warp. Sharp cannot do that, and adding it is out of scope. A poster composited flat onto an angled wall looks wrong instantly.
Blank wall area Nothing already hanging where the poster goes. The tool composites on top; it does not erase what is underneath.
Obvious light direction You declare it as left or right, and the shadows follow. Ambiguous lighting gives you nothing to declare.
Room for the widest aspect One rectangle serves every poster. Measure it against the widest artwork in the catalogue or panoramas will sit awkwardly.
Phone photographs are safe

EXIF rotation is honoured: both the room photograph and the artwork are auto-oriented before anything is measured or composited, so a portrait shot straight off a phone renders the way it looks in your photo viewer, not the way the camera stored its pixels.

Watermark hazard

If you generate rooms with AI, do not seed them from the reference artwork in .cache/seed-media/. Those images have a MESON ART watermark baked into the pixels, and it will propagate into every mockup you produce.

Running it

Steps one to three are once per room template. Four onward are once per batch of posters.

  1. 1

    Put the room photographs in place

    Drop them in .cache/room-templates/. That directory is git-ignored on purpose — room photographs are large and get regenerated, and every discarded revision would live in git history forever.

  2. 2

    Measure the wall rectangle

    Open the photograph and note the pixel bounds of the area the artwork should occupy. Divide each by the image's own dimensions to get numbers between 0 and 1. Takes about a minute.

    Worked example · a 1600 × 1600 room photograph
    left edge   458 / 1600 = 0.286   →  x
top edge     75 / 1600 = 0.047   →  y
width       773 / 1600 = 0.483   →  w
height      995 / 1600 = 0.622   →  h

"placement": { "x": 0.286, "y": 0.047, "w": 0.483, "h": 0.622 }

    Normalised values mean you can re-export the photograph at a different resolution without measuring again.

    It is a bounding box, not a target

    The artwork is fitted inside the rectangle at its own aspect ratio and centred. It is never stretched to fill it. A portrait poster and a landscape poster both land correctly in the same room, one leaving margin at the sides and the other at the top and bottom.

  3. 3

    Describe the template

    Add an entry to packages/api/src/database/room-templates.json. This file is tracked in git — the measurements are the intellectual content, and they need to be reviewable in a diff.

    packages/api/src/database/room-templates.json
    [
  {
    "id": "living-room-warm",
    "file": "living-room-warm.jpg",
    "placement": { "x": 0.286, "y": 0.047, "w": 0.483, "h": 0.622 },
    "light": "left",
    "frame": "wood",
    "label": "Living room"
  }
]
  4. 4

    Dry run first

    Validates every template, confirms every referenced image exists, and reports what it would render — without writing anything. Cheap, and worth doing before a long batch.

    packages/api
    bun run mockups:rooms --posters ./art --dry-run
  5. 5

    Generate

    packages/api
    bun run mockups:rooms --posters ./art

    One poster failing does not stop the batch. Failures are collected, reported at the end with the poster name and reason, and the process exits non-zero.

    The output folder is not cleaned between runs

    Re-running against the same --out directory does not clear it first. Delete a room shot from the contact sheet, run again without --only, and the deleted file comes back. A --only re-run is additive too — the earlier run's room-*.jpg files stay on disk beside the new ones.

    A poster that fails partway through keeps whatever it had already written. A poster's folder missing contact-sheet.jpg is an interrupted run, not a finished one where nothing survived review.

  6. 6

    Review and cull

    Open out/<poster-name>/contact-sheet.jpg. Every candidate is there, numbered, with its room label underneath. Delete the files you don't want from the output folder. Whatever survives is your set — there is no marking step that could disagree with what is on disk.

  7. 7

    Hand off

    Either upload the survivors through the admin product form one at a time, or point the bulk catalogue import at the output folder.

    Bulk import manifest · roomImages is pipe-separated
    mainImage,roomImages
framed-main.jpg,room-living-room-warm.jpg|room-reading-nook.jpg

Command reference

FlagDefaultWhat it does
--posters <dir> required Directory of artwork files. Reads .jpg, .jpeg, .png, .webp; ignores everything else.
--templates <dir> .cache/room-templates Where the room photographs live.
--out <dir> ./out Where results are written, one subfolder per poster.
--only <id,id> all Render a subset of templates by id. Order follows the template file, not your list, so contact-sheet numbering stays stable between runs.
--frame <slug> per template Override every template's declared moulding for this run.
--dry-run off Validate and report. Writes nothing at all.
A typo is an error, not a shrug

An unrecognised flag stops the run. Misspelling --templates must not silently fall back to the default directory and render against the wrong rooms.

Template fields

room-templates.json

FieldTypeNotes
idstringUnique. Becomes the output filename: room-<id>.jpg.
filestringFilename inside the templates directory.
placementobjectx, y, w, h, each 0–1. Must fit inside the image: x + w and y + h cannot exceed 1.
light"left" · "right"Which way the room's light falls. Sets shadow direction.
framestringA key in frame-renders.json.
labelstringShown under the thumbnail on the contact sheet.

frame-renders.json

Keyed by moulding slug, matching the catalogue's frame records. Ships with wood, black, white, gold, silver and frameless. rolled is excluded on purpose: a rolled canvas ships in a tube and is never hung, so it has no room shot.

FieldTypeNotes
widthRationumber Frame face width as a fraction of the artwork's short edge, so a panoramic poster isn't swallowed by a frame proportioned to its length. 0 means frameless.
color[r, g, b] Face colour, each channel 0–255.
depthRationumber How far the piece stands off the wall, same units. Must be above zero — everything hung stands off the wall, and a zero would flatten a frameless canvas completely.

When it refuses

Every failure names what is wrong and which template caused it. Nothing is clamped, defaulted, or skipped quietly — a plausible-looking wrong image costs far more than a run that won't start.

MessageFix
No room templates defined — nothing to render. Expected on a fresh checkout. room-templates.json is still []. Add entries.
Room template "…" references a missing image: … The file isn't in the templates directory. Check the name, or point --templates somewhere else.
Room template "…" names frame "…", which has no render spec. Add that slug to frame-renders.json, or use one that exists.
… placement must lie entirely inside the image x + w or y + h exceeds 1. Re-measure.
Room template "…" is declared more than once. Two entries share an id. Ids become filenames, so one would overwrite the other.
Room template "" is invalid: id … An entry has a blank id. The message can't name which row — check for an unfilled copy-pasted entry.
Frame render "…" is invalid: … A colour channel outside 0–255, or a depthRatio of zero.
Unknown flag: … Typo. See the command reference.
--posters <dir> is required. No input directory given.
No poster images found in … Directory is empty, or the files aren't .jpg, .jpeg, .png or .webp.
--frame "…" has no render spec. The override slug isn't in frame-renders.json.
Flag … was passed more than once. The same flag appears twice on the command line. The second value would otherwise silently win. Pass it once.
Poster filenames collide on the same output folder — rename one of each: … Two posters share a basename once the extension is stripped (e.g. sunset.jpg and sunset.png) — both map to the same out/<slug>/ folder, and one would silently overwrite the other. Rename one of them.

What it won't do

Each of these was decided against on purpose. Knowing why saves you rediscovering the reasoning.

Not includedReasoning
Generating the room photographs They are supplied. This tool consumes them.
Angled or perspective rooms Needs a four-point homography. Sharp offers an affine transform but no perspective warp, so this would be a different design rather than an extension.
An admin screen Review is a contact sheet and deleting files. A UI would need an endpoint, a job, an upload path, and would duplicate the bulk importer.
Detecting the wall automatically Measured by eye once per template, in about a minute. Not worth the failure modes.
A room shot per frame Choosing a frame on the product page changes the price and the cart, never the gallery image — so there is nowhere to display them. Each template declares the one moulding that suits its palette.
Squaring the main image The upload pipeline already mats, squares and measures every upload. Doing it here too would put the square contract in two places, and they would drift.
Writing to the database or object storage Keeping it a leaf is what makes it small and safe to re-run.
